# Maintainers Guide для METR

## Overview

Руководство для maintainers проекта METR.

## Responsibilities

### Code Review
- Review pull requests
- Ensure code quality
- Maintain code standards

### Issue Management
- Triage issues
- Assign labels
- Close stale issues

### Release Management
- Plan releases
- Create release notes
- Deploy releases

### Community
- Answer questions
- Help contributors
- Maintain documentation

## Review Process

### Review Checklist
- [ ] Code follows style guide
- [ ] Tests are added
- [ ] Documentation updated
- [ ] No breaking changes (or documented)
- [ ] CI/CD passing

### Review Guidelines
- Be constructive
- Be timely (within 24h)
- Be thorough
- Be respectful

## Release Process

### Planning
1. Review completed features
2. Plan release date
3. Create release branch
4. Update version

### Execution
1. Merge release branch
2. Create tag
3. Build artifacts
4. Deploy to stores

### Post-Release
1. Monitor metrics
2. Collect feedback
3. Plan next release

## Communication

### Channels
- GitHub Discussions
- Discord
- Email

### Frequency
- Daily: Check issues/PRs
- Weekly: Team sync
- Monthly: Roadmap review

## Best Practices

1. **Be Responsive**: Отвечайте быстро
2. **Be Helpful**: Помогайте contributors
3. **Be Fair**: Справедливые решения
4. **Be Transparent**: Прозрачность процесса
